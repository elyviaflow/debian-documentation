# 🤝 Contributing Guide

Thank you for your interest in contributing to this project.

This repository aims to provide clean, beginner-friendly, and practical Debian server documentation for multiple Debian versions.

---

# 📋 Before Contributing

Please make sure that:

- Documentation is clear and easy to understand
- Commands are tested before submission
- Markdown formatting is consistent
- Folder structure is followed correctly
- Explanations remain beginner-friendly

---

# 📁 Project Structure

Example structure:

```text
debian-11-bullseye/
├── installation/
├── web-server/
├── databases/
├── application/
├── security/
└── troubleshooting/
```

Each Debian version should maintain the same structure whenever possible.

---

# 🚀 How to Contribute

## 1. Fork the Repository

Fork this repository to your own GitHub account.

---

## 2. Create a Branch

Create a new branch for your changes:

```bash
git checkout -b fix/topic-name
```

Examples:

```bash
git checkout -b docs/nginx-ssl-guide
git checkout -b fix/mariadb-installation
git checkout -b improve/phpmyadmin-setup
```

---

## 3. Make Your Changes

You can contribute by:

- Adding new documentation
- Fixing outdated commands
- Improving explanations
- Correcting grammar or formatting
- Adding Debian version compatibility notes

---

## 4. Commit Your Changes

Use clear and descriptive commit messages:

```bash
git commit -m "fix: improve nginx configuration guide"
```

Examples:

```bash
git commit -m "docs: add Debian 13 installation guide"
git commit -m "fix: correct MariaDB repository command"
git commit -m "improve: simplify SSH hardening explanation"
```

---

## 5. Push and Open a Pull Request

Push your branch:

```bash
git push origin fix/topic-name
```

Then open a Pull Request on GitHub.

---

# 📝 Documentation Style

Recommended guidelines:

- Use simple and readable English
- Keep explanations concise
- Separate commands into code blocks
- Add notes for Debian version differences
- Avoid unnecessary complexity

---

# ⚠️ Important Notes

- Do not submit untested commands
- Avoid AI-generated spam documentation
- Keep tutorials practical and realistic
- Preserve the existing project structure

---
